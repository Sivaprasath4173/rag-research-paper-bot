Project Overview

What This Project Builds

📚

Corpus Ingestion

Load & audit PDF papers. Extract metadata (filename, page number, char count). Two high-quality research papers.

🧠

Dual Embedding

Index all chunks into ChromaDB using two state-of-the-art open-source embedding models for comparison.

🔎

Hybrid Retrieval

Combine dense vector search with BM25 keyword search. Weighted fusion (α=0.5) outperforms either alone.

🤖

LLM Generation

Feed retrieved context to Google Gemini via a strict grounded-answer prompt. No hallucination permitted.

📊

Batch Evaluation

10 test questions systematically exercising factual recall, "I don't know" triggering, and citation accuracy.

🖥️

Streamlit UI

Live interactive demo. Sidebar shows LLM. Query box, answer panel, and collapsible source expanders.

chunk_size=500 · chunk_overlap=50

→ 246 chunks · avg 441 chars · max 500

Finer granularity. Better for narrow factual Q&A. More retrieval candidates. Works well with 3k token context window.

Config B

chunk_size=1000 · chunk_overlap=150

→ 132 chunks · avg 879 chars · max 1000

Broader context per chunk. Risk of retrieving chunks that mix multiple topics. Higher token cost per LLM call.

Technical Architecture

Full Technology Stack

📄 PDF Loading

PyPDFLoader (langchain-community)

Preserves page metadata; explicit filename & page_display fields added

✂️ Chunking

RecursiveCharacterTextSplitter

500 chars / 50 overlap. Paragraph-first splitting preserves sentence boundaries

🧠 Embeddings

HuggingFaceEmbeddings (local CPU)

bge-m3 (production) + mxbai-embed-large-v1 (comparison). normalize=True

🗄️ Vector Store

ChromaDB (persistent)

Two persistent collections. Survives kernel restart. On-disk at ./chroma_db/

🔎 BM25

rank-bm25 (BM25Okapi)

In-memory index over all chunks. Normalised scores fused with dense scores at α=0.5

⛓️ LangChain LCEL

langchain-core RunnableLambda

Declarative pipeline. retrieve | format | prompt | llm | parser. Streamable.

ChatGoogleGenerativeAI

gemini-flash-latest · temperature=0 · strict grounded-answer prompt

Streamlit ≥1.35.0

Conclusions & Next Steps

Key Takeaways

What We Proved

  • Hybrid retrieval (BM25 + dense) consistently outscores dense-only
  • Strict grounded prompts eliminate hallucination on out-of-corpus questions
  • chunk_size=500 gives better factual precision than 1000
  • bge-m3 produces richer semantic matches for scientific text than mxbai

Immediate Next Steps

  • Submit finalized notebook and project artifacts for evaluation
  • Run 5-query live demo on Streamlit for viva
  • Upgrade OPENAI_API_KEY to enable mxbai-embed-3-small comparison
  • Add streaming support (LLM response → Streamlit st.write_stream)

Future Improvements

  • Re-ranking layer (cross-encoder) for top-k results
  • Query rewriting for complex multi-hop questions
  • Expand corpus: more papers, lecture slides
  • Evaluation with RAGAS framework (faithfulness, relevancy)
